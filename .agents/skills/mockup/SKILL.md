# HTML Mockup

## Purpose

全体要件から人間が選んだ利用者フローについて、画面遷移、情報の見せ方、操作の流れを具体化し、議論を助ける簡易HTMLモックを作る。モックは仮説の可視化であり、正解、要件承認、技術設計、製品の完成形を表さない。

## Inputs

- 人間が選んだ利用者、目的、業務フロー、確認したい論点
- `docs/project-requirements.md` の関連FR/NFR
- 既存のconstitution、関連spec、デザイン規約（存在する場合）
- 保存先の指定。指定がなければ `work/mockups/<flow-slug>/` を使う

## Steps

1. AGENTS.md、WORKFLOW.md、全体要件、constitution、関連specを確認する。
2. 人間が選んだ利用者フローと、このモックで確認したい問いを短く記録する。全システムや複数の独立フローを一括でモック化しない。
3. 確認したい流れを示す最小限の静的HTML/CSS/JavaScriptを作る。外部サービス接続、実データ、認証情報、永続化、バックエンドを追加しない。画面間の移動や主要な操作が理解に必要な場合だけ、簡単なクリック動作を付ける。
4. 仮の文章・データ・状態を明示し、見た目だけでなく利用者が何を確認し、次に何をできるかが分かるようにする。
5. 成果物を提示し、画面や流れへの意見を記録する。意見をそのまま正解とせず、「人間が決める業務判断」「検証する仮説」「未決事項」「却下・保留」に分ける。権限、公開可否、保持期間、削除方針などを推測で決めない。
6. 次に進む前に、人間が対象とする縦切りを一つ選び、その範囲と受入可能な価値を確認する。モック作成だけを根拠にrequirementsのReviewを完了扱いにしない。
7. 一時成果物の場合、合意した縦切りのrequirementsへ必要な判断・仮説・未決事項を移した後、モックと中間ファイルを `work/` から削除する。保存を求められた場合のみ、指定されたレビュー用の場所へ残す。

## Output

- 選択したフローを示す簡易HTMLモック
- 確認したい問いと、観察された人間判断・仮説・未決事項の短いメモ

## Boundaries

- モックを唯一の要求 source of truth にしない。要求・設計・受入条件は別途、SDDで明文化して人間レビューを受ける。
- モックの見た目や操作を、技術構成・データモデル・APIの承認と解釈しない。
- ユーザーが選んでいない機能を追加せず、利用者向けの業務判断をAIの推測で補わない。
- モックはアプリ本体のruntimeや本番成果物へ混ぜない。
- インタラクションや情報構造を確認することが目的。見栄えを磨き込んだ完成デザインを作る工程ではない。

## Stop condition

人間がフローを確認し、次に仕様化する一つの縦切りを選んだら終了する。requirementsの作成、設計、実装へ自動で進まない。
