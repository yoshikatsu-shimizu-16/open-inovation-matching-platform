# Requirements: 共創マッチング初期体験（再定義・レビュー案）

> 元の機能別SPEC案を一時保管した草案。全体要件とconstitutionのレビュー後にFR/NFRへ対応付けて再整理する。
> 参照先との採用判断と段階計画は [legacy-comparison.md](legacy-comparison.md) を参照する。設計・実装の承認を意味しない。

## Overview

相談者が言語化しきれていない目的、保有資源、不足能力、共創相手への期待、実行条件を、AIとの対話で明らかにする。相談者が共創仮説と構造化された課題を確認・修正した後、確定課題に基づく候補と適合点・不足点・根拠を確認できる初期体験を提供する。

入力が「架空」か「実際」かをシステムは判定しない。利用者の入力を起点とし、未確認事項は未確認として扱う。開発・自動検証はローカルで行い、想定実行環境は Cloudflare とする。

対話の観点は ISO 56000 系列、とくにギャップ分析、相手の特定・評価、価値と課題の認識合わせを扱う [ISO 56003:2019 の公開要約](https://www.iso.org/standard/68929.html) と参照先システムの実装に基づく。ISO 本文の全条項への適合や認証を主張するものではない。

## Users and primary flow

- 主利用者は、自組織の課題と共創機会を整理したい相談者。初期検証では運営者が相談者役を務めることもできる。
- 相談開始 → 5カテゴリでの聞き取り → 共創仮説の確認・修正 → 課題プロフィールの確認・修正・確定 → 候補評価と根拠の確認、の順に進む。
- 共創の可能性は検討仮説として示し、相談内容の真偽や事業上の妥当性をAIが断定しない。

## User stories

- As a 相談者, I want 自分の説明に応じてAIに不足情報を聞き取ってほしい, so that 課題と共創の可能性を明確にできる。
- As a 相談者, I want 共創仮説と課題プロフィールを確認・修正したい, so that 意図した条件だけを候補評価に使える。
- As a 相談者, I want 候補の適合点・不足点・根拠を確認したい, so that 次に確認すべきことを判断できる。
- As a 運営者, I want 対話・AI出力・評価の再現と失敗時の回復を確認したい, so that 初期体験を評価できる。

## Requirements (EARS)

### 相談と課題の明確化

- [ ] REQ-001: WHEN 相談者が相談を開始する THE SYSTEM SHALL 相談状態を作成し、最初の問いを表示する。
- [ ] REQ-002: THE SYSTEM SHALL 「目的・背景・困りごと」「保有能力・提供資源」「不足能力・ギャップ」「相手種別・連携形態」「条件・制約」の5カテゴリを扱い、参照先の13項目それぞれの確認状況を管理する。
- [ ] REQ-003: WHEN 相談者が自由記述、選択肢、またはフォームで回答する THE SYSTEM SHALL 回答を該当項目へ反映し、確認済み・不足情報に応じて次の問いを表示する。
- [ ] REQ-004: WHILE 確認が必要な項目が残る THE SYSTEM SHALL 必要に応じて深掘りし、現在のカテゴリ、確認状況、次にできる操作を表示する。カテゴリ遷移はアプリケーションが管理する。
- [ ] REQ-005: WHEN 相談者が答えられない項目をスキップする THE SYSTEM SHALL その項目を未確認として扱い、事実を補わずに対話を進める。
- [ ] REQ-006: WHEN 対話に必要な確認が終わる THE SYSTEM SHALL 回答で裏付けられた課題と共創可能性を仮説として提示し、相談者が確認または修正できるようにする。
- [ ] REQ-007: WHEN 相談者が仮説を確認または修正する THE SYSTEM SHALL 確認結果と対話内容に基づき、目的・背景、保有資源、課題、必要能力、相手への期待、連携形態、制約、未確認事項を含む課題プロフィールの下書きを生成する。
- [ ] REQ-008: WHILE 課題プロフィールが未確定である THE SYSTEM SHALL 相談者が各項目を確認・修正できるようにし、候補評価を開始しない。
- [ ] REQ-009: WHEN 相談者が課題プロフィールを明示的に確定する THE SYSTEM SHALL 確定した版だけを候補評価の入力として保持する。

### 候補と共創可能性

- [ ] REQ-010: WHEN 確定課題から候補評価を開始する THE SYSTEM SHALL 候補の公開状態と明示された制約を確認し、必要能力、資源の補完性、連携形態、実現可能性を評価する。
- [ ] REQ-011: THE SYSTEM SHALL 候補の最終順位を版管理された決定的な評価規則で決め、AIに順位を決定させない。
- [ ] REQ-012: WHEN 候補を表示する THE SYSTEM SHALL 各候補の適合点、不足点、評価根拠、未確認事項を示し、共創可能性を確約ではなく検討仮説として表現する。
- [ ] REQ-013: IF 適格候補がない、または候補取得に失敗する THEN THE SYSTEM SHALL 状態を区別して表示し、課題の見直しまたは再試行に進めるようにする。
- [ ] REQ-014: WHEN 同一版の課題、候補、評価規則で評価を繰り返す THE SYSTEM SHALL 同じ最終順位と評価内訳を返す。

### 実行環境、データ、安全性

- [ ] REQ-015: THE SYSTEM SHALL React/Vite の画面、Hono の API、Cloudflare Workers の実行境界に沿って主要フローを提供し、ローカル開発と Cloudflare preview で検証可能にする。
- [ ] REQ-016: THE SYSTEM SHALL 相談状態、確定課題、評価入力と結果の版をサーバー側で保持し、再表示・障害回復・評価根拠の確認に利用できるようにする。保存先と保持期間の詳細は設計で定める。
- [ ] REQ-017: WHEN AIが対話・仮説・課題プロフィールを生成する THE SYSTEM SHALL サーバー側から呼び出し、定義済みの出力契約で検証してから利用する。
- [ ] REQ-018: IF AI呼び出しまたは出力検証が失敗する THEN THE SYSTEM SHALL 確認済み入力を失わず、失敗と再試行方法を表示する。
- [ ] REQ-019: THE SYSTEM SHALL AIの認証情報をブラウザに公開せず、コード・仕様・サンプルに埋め込まない。
- [ ] REQ-020: WHEN 相談者が秘密情報・個人情報・未公開知財の詳細を入力しようとする THE SYSTEM SHALL 抽象化した記述を促し、候補や契約条件について未確認の事実を断定しない。
- [ ] REQ-021: WHERE 自動検証環境である THE SYSTEM SHALL 外部AIに依存しない制御可能な応答で主要フローを検証できるようにする。
- [ ] REQ-022: WHEN AIが相談者へ質問または課題の解釈を提示する THE SYSTEM SHALL 版管理された読み取り専用の対話ルールと出典情報を参照できるようにし、出典で裏付けられない相談者固有の事実を作らない。
- [ ] REQ-023: WHEN 候補プロフィールを評価に使用する THE SYSTEM SHALL その候補の公開可否、能力・提供資源、連携条件、情報の出典または未確認状態を識別できるようにする。

## Acceptance criteria

- [ ] 任意の相談入力から、5カテゴリ・13項目の確認状況を使った対話、仮説の確認、課題の修正・確定、候補結果まで進める。
- [ ] 未回答・未確認事項が既知の事実として混入せず、未確定の課題では候補評価できない。
- [ ] 同じ確定課題・候補集合・評価規則から同じ順位と内訳が得られ、適合点・不足点・根拠を確認できる。
- [ ] AI障害、候補なし、候補取得障害を区別して回復操作を提示し、確認済み入力を保持する。
- [ ] ローカルで自動検証し、Cloudflare preview 上で主要フローを検証できる。production 公開は今回の受入条件に含めない。

## Design decisions to resolve after review

- 候補プロフィールの収集・公開審査方法、初期候補集合の内容と出典、相談データの保持期間と削除手段。
- Cloudflare 上の相談・監査情報の保存設計、セッション識別とアクセス制御、preview の利用範囲。
- 初期版の候補取得方法（キーワードまたはセマンティック検索）、評価項目・重み・同点処理、根拠表示の粒度。
- ISO 56003 本文を利用できる場合の条項単位の照合方法。現時点では公開要約と参照先実装を根拠とする。

## Out of scope for the initial experience

- 本番公開、一般利用者への開放、面談・PoC・契約の実行、決済。
- 認証・組織管理、候補組織の自動調査・登録、専門家によるルール編集、フィードバックに基づく自動改善。導入順は比較表で管理する。
- 参照先の Next.js/Vercel/Neon/pgvector 実装やデータをそのまま移植すること。実データや認証情報のコピー。
- ISO 56003 への正式な適合宣言、AIによる契約・知財・規制上の結論。
