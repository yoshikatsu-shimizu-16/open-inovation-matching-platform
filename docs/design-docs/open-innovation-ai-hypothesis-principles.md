- Confirmed: 2026-09-26

## Context

オープンイノベーションを求める相談者は、自組織の課題や不足能力だけでなく、どのような共創の可能性が存在するか自体を知らない場合がある。

そのため、AIを単なる聞き取り・要約装置として扱うだけでは、相談者がすでに知っている範囲の整理に閉じてしまう。一方で、AIの推察を確認済みの事実として混ぜると、相談者が述べていない内容が事実として扱われる危険がある。

人間のコンサルタントがヒアリング結果から提案を行い、相談者がその提案を採用・修正・却下するのと同じように、AIにも可能性探索の提案役を持たせる。ただし、相談者が述べた事実との境界を崩さない。

## Principles

### 1. 相談者の入力・確認済み事項とAI仮説を分離する

相談者自身が入力・確認した内容は、AIが推察した内容と区別して扱う。

AIが生成した推察、解釈、共創案、可能性は、相談者の事実として自動的に昇格させない。

### 2. AIは可能性探索のために推察を含む提案をしてよい

AIは、相談者が明示していない共創相手、連携方法、技術、資源の組み合わせなどについて、可能性を広げる目的で仮説を提案してよい。

これは事実の補完ではなく、オープンイノベーションの選択肢を探索するための提案である。

「相談者が思いつかなかったが、検討する価値のある可能性」を提示できることを、このプロダクトにおけるAIの重要な価値とする。

### 3. 推察は推察として示す

AIの提案は、確定事項ではなく仮説・提案・検討候補であることが利用者に分かる形で提示する。

将来のSPECでは、必要に応じて次の情報の表示方法を検討する。

- どの相談者入力を手掛かりにした提案か
- AIがどのように解釈したか
- 未確認事項や不確実性
- 追加確認が必要な点

具体的な表示形式は後続SPECで決める。

### 4. 相談者が採用・修正・却下できる

AI仮説は相談者に選択権を残す。

相談者は提案をそのまま採用してもよく、一部を修正してもよく、意図に合わなければ却下できる。

相談者が採用または修正した内容だけを、後続の課題整理へ反映する。AI出力だけで確認済み事実や確定課題へ変更しない。

### 5. 「意外性」と「事実性」を別の軸として扱う

AIの提案が相談者にとって意外であること自体は問題ではない。むしろ、オープンイノベーションでは既知の選択肢の外側を探索できることに価値がある。

一方、意外な提案であっても、それを裏付けられた事実であるかのようには表示しない。

## Mockup review decisions relevant to later features

2026-09-26 のモックレビューで、以下も人間判断として確認した。

- 初回相談は自由記述で開始する。入力者が迷わないよう、入力欄には具体的かつ特定業界に偏りすぎないプレースホルダー例を表示する。
- 5カテゴリ・13項目を扱う後続の聞き取りでは、利用者が現在位置と残量を把握できるよう進捗を継続表示する。
- 後続の聞き取りでは「未回答」と「わからない」を同一状態にしない。相談者が自組織のすべてを把握しているとは限らないため、明示的な「わからない」という回答を許容する。
- 課題プロフィールの確定操作は、相談開始SPECでは決めず、該当する後続機能で扱う。

## Scope boundary

この文書は将来の機能で守るプロダクト原則を記録するもので、今回の `F001-consultation-start` SPECにAI仮説生成機能を追加するものではない。

具体的な画面、AI出力契約、プロンプト、採用・修正・却下の操作、保存状態は、対応する縦切りを選択した時点で個別のrequirements / designとして定義する。
