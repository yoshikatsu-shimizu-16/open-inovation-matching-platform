## Overview

相談者が言語化しきれていない目的、保有資源、不足能力、共創相手への期待、実行条件をAIとの対話で明らかにする。相談者が共創仮説と構造化された課題を確認・修正・確定した後、その確定版だけを使って候補を評価し、適合点・不足点・根拠・未確認事項を確認できる初期体験を提供する。

入力が「架空」か「実際」かをシステムは判定しない。利用者の入力を事実の起点とし、未確認事項は未確認として保持する。開発・自動検証はローカルで行い、想定実行環境はCloudflare previewとする。

## User stories

- As a 相談者, I want 自分の説明に応じて不足情報をAIに聞き取ってほしい, so that 課題と共創の可能性を整理できる。
- As a 相談者, I want 共創仮説と課題プロフィールを確認・修正したい, so that 自分が確定した条件だけを候補評価に使える。
- As a 相談者, I want 候補ごとの適合点・不足点・根拠・未確認事項を確認したい, so that 次に確認すべきことを自分で判断できる。
- As a 運営者, I want 対話・AI出力・候補評価を再現し、障害時にも確認済み入力を保持したい, so that 初期体験の妥当性を検証できる。

## Requirements (EARS)

### 相談と課題の明確化

- [ ] REQ-001: WHEN 相談者が相談を開始する THE SYSTEM SHALL 相談状態を作成し、最初の問いと現在の進行状況を表示する。
- [ ] REQ-002: THE SYSTEM SHALL 「目的・背景・困りごと」「保有能力・提供資源」「不足能力・ギャップ」「相手種別・連携形態」「条件・制約」の5カテゴリを扱い、参照先で定義された13項目それぞれの確認状況を管理する。
- [ ] REQ-003: WHEN 相談者が自由記述、選択肢、またはフォームで回答する THE SYSTEM SHALL 回答を該当項目へ反映し、確認済み情報と不足情報に応じて次の問いを表示する。
- [ ] REQ-004: WHILE 確認が必要な項目が残る THE SYSTEM SHALL 必要に応じて深掘りし、現在のカテゴリ、確認状況、次に実行できる操作を表示する。
- [ ] REQ-005: WHEN 相談者が回答できない項目をスキップする THE SYSTEM SHALL その項目を未確認として保持し、事実を補完せずに対話を継続する。
- [ ] REQ-006: WHEN 対話に必要な確認が終わる THE SYSTEM SHALL 回答で裏付けられた課題と共創可能性を仮説として提示し、相談者が確認または修正できるようにする。
- [ ] REQ-007: WHEN 相談者が共創仮説を確認または修正する THE SYSTEM SHALL 確認結果と対話内容に基づき、目的・背景、保有資源、課題、不足能力、相手への期待、連携形態、制約、未確認事項を含む課題プロフィールの下書きを生成する。
- [ ] REQ-008: WHILE 課題プロフィールが未確定である THE SYSTEM SHALL 相談者が各項目を確認・修正できるようにし、候補評価を開始しない。
- [ ] REQ-009: WHEN 相談者が課題プロフィールを明示的に確定する THE SYSTEM SHALL 確定した版だけを候補評価の入力として保持する。

### 候補と共創可能性

- [ ] REQ-010: WHEN 確定課題から候補評価を開始する THE SYSTEM SHALL 候補の公開状態と明示された制約を確認し、公開不可の候補を除外したうえで必要能力、資源の補完性、連携形態、実現可能性を評価する。
- [ ] REQ-011: THE SYSTEM SHALL 候補の最終順位を版管理された決定的な評価規則で決め、AIに最終順位を決定させない。
- [ ] REQ-012: WHEN 候補を表示する THE SYSTEM SHALL 各候補の適合点、不足点、評価根拠、未確認事項を示し、共創可能性を確約ではなく検討仮説として表現する。
- [ ] REQ-013: IF 適格候補がない、または候補取得に失敗する THEN THE SYSTEM SHALL 状態を区別して表示し、課題の見直しまたは再試行に進めるようにする。
- [ ] REQ-014: WHEN 同一版の課題、候補、評価規則で評価を繰り返す THE SYSTEM SHALL 同じ最終順位と評価内訳を返す。

### 実行環境、データ、安全性

- [ ] REQ-015: THE SYSTEM SHALL React/Viteの画面、HonoのAPI、Cloudflare Workersの実行境界に沿って主要フローを提供し、ローカル開発とCloudflare previewで検証可能にする。
- [ ] REQ-016: THE SYSTEM SHALL 相談状態、確定課題、評価入力と結果の版をサーバー側で保持し、再表示、障害回復、評価根拠の確認に利用できるようにする。
- [ ] REQ-017: WHEN AIが対話、共創仮説、または課題プロフィールを生成する THE SYSTEM SHALL サーバー側からAIを呼び出し、定義済みの出力契約で検証してから利用する。
- [ ] REQ-018: IF AI呼び出しまたはAI出力の契約検証に失敗する THEN THE SYSTEM SHALL 確認済み入力を失わず、失敗状態と再試行方法を表示する。
- [ ] REQ-019: THE SYSTEM SHALL AIの認証情報をブラウザへ公開せず、コード、仕様、サンプルへ埋め込まない。
- [ ] REQ-020: WHEN 相談者が秘密情報、個人情報、または未公開知財の詳細を入力しようとする THE SYSTEM SHALL 抽象化した記述を促し、候補や契約条件について未確認の事実を確定情報として扱わない。
- [ ] REQ-021: WHERE 自動検証環境である THE SYSTEM SHALL 外部AIの実応答に依存しない制御可能な応答で、正常系、未回答、AI障害、候補なし、候補取得障害を検証できるようにする。
- [ ] REQ-022: WHEN AIが相談者へ質問または課題の解釈を提示する THE SYSTEM SHALL 版管理された読み取り専用の対話ルールと出典情報を参照し、出典で裏付けられない相談者固有の事実を生成せず、根拠と未確認事項を区別できるようにする。
- [ ] REQ-023: WHEN 候補プロフィールを評価に使用する THE SYSTEM SHALL その候補の公開可否、能力・提供資源、連携条件、情報の出典または未確認状態を識別できるようにする。
- [ ] REQ-024: WHERE Cloudflare previewを利用する THE SYSTEM SHALL 許可された利用者と相談単位のアクセス境界を設け、別相談のデータや許可されていない相談内容を参照できないようにする。
- [ ] REQ-025: WHEN 相談内容または未公開知財をログへ記録する THE SYSTEM SHALL 機密本文を一般ログへ無制限に出力せず、運用上必要な最小限の識別情報と状態に制限する。

## Acceptance criteria

- [ ] 任意の相談入力から、5カテゴリ・13項目の確認状況を使った対話、共創仮説の確認、課題プロフィールの修正・確定、候補評価結果まで進める。
- [ ] 未回答・未確認事項が確認済みの事実として混入せず、未確定の課題プロフィールでは候補評価を開始できない。
- [ ] 同じ確定課題、候補集合、評価規則から同じ順位と評価内訳が得られ、候補ごとの適合点、不足点、根拠、未確認事項を確認できる。
- [ ] AI障害、AI出力検証失敗、候補なし、候補取得障害を区別して回復操作を提示し、確認済み入力を保持する。
- [ ] ローカルで外部AIに依存せず主要フローを自動検証でき、Cloudflare preview上でも段階1〜2の主要フローを確認できる。
- [ ] previewでは利用者・相談単位のアクセス境界が機能し、機密本文が一般ログへ無制限に出力されないことを検証できる。

## Open decisions before design

requirementsのレビュー後、`sdd-plan`で設計へ進む前または設計中に、次の未決事項を具体化する。

- 初期候補集合の入手先、出典、公開審査方法、更新方法。
- 相談データの保持期間、削除手段、Cloudflare上の保存先、セッション識別方式。
- previewを利用できる人の範囲とアクセス制御方式。
- 候補評価の観点、重み、同点処理、説明の粒度、初期候補取得方式。
- ISO 56003本文を利用できる場合に条項単位の照合を行うか。

## Out of scope

- 本番公開、一般利用者への開放、面談・PoC・契約締結・決済の実行。
- `FR-012`〜`FR-015`で扱う正式運用向けの認証・組織管理、候補組織の調査・登録・審査、専門家によるルール管理、評価フィードバック。
- 初期検証の結果を待たずにセマンティック検索やpgvectorを前提化すること。
- 参照先システムのNext.js、Vercel、Neon、pgvector実装や実データ、認証情報をそのまま移植すること。
- ISO 56003への正式な適合宣言、AIによる協業可否、契約、知財、規制上の確定判断。

## Constitution alignment

- `P-001`: REQ-003, REQ-005, REQ-017, REQ-020, REQ-022で、相談者入力を事実の起点とし、未確認事項を事実として補完しない。
- `P-002`: REQ-006〜REQ-009で、人の確認と明示的な課題確定を候補評価への境界にする。
- `P-003`: REQ-017〜REQ-018, REQ-022〜REQ-023で、AI出力、対話ルール、情報源を検証・追跡可能にする。
- `P-004`: REQ-010〜REQ-014で、候補評価の公開条件、決定的な順位付け、根拠、再現性を定義する。
- `P-005`: REQ-019〜REQ-020, REQ-023〜REQ-025で、認証情報、相談内容、未公開知財、候補公開状態を保護する。
- `P-006`: REQ-013, REQ-016, REQ-018で、障害時にも確認済み入力を保持し回復可能にする。
- `P-007`: REQ-015〜REQ-016で、React/Vite、Hono、Cloudflare Workersの責務境界を前提にする。
- `P-008`: 本SPECを実装前の契約とし、REQ-021で外部AIに依存しない主要フロー検証を要求する。
- `P-009`: 初期版を段階1〜2に限定し、段階3の機能と検索高度化をOut of scopeに置く。
