## Overview

相談者が自由記述で相談内容を入力し、相談状態を開始して次の聞き取り工程へ進める入口を提供する。

このSPECは「相談開始」だけを対象とし、不足情報の聞き取り、13項目の回答管理、AIによる共創仮説の生成、課題プロフィールの確認・確定は後続の独立した機能ループで扱う。

## User stories

- As a 相談者, I want 自分の状況を自由な文章で入力して相談を始めたい, so that 最初から決められた分類を理解していなくても課題整理を開始できる。
- As a 相談者, I want 入力例を見ながら相談内容を書きたい, so that 何を入力すればよいか分からず開始できない状態を避けられる。
- As a 相談者, I want 相談開始に失敗しても入力内容を失わず再試行したい, so that 同じ相談内容を入力し直さずに済む。

## Requirements (EARS)

- [ ] REQ-001: WHEN 相談開始画面を表示する THE SYSTEM SHALL 相談内容を自由記述できる入力欄と相談開始操作を表示する。
- [ ] REQ-002: WHEN 相談開始画面を表示する THE SYSTEM SHALL 入力欄に、相談者が何を書けばよいか理解できる具体的な入力例をプレースホルダーとして表示する。
- [ ] REQ-003: WHEN 相談者が空白文字だけではない相談内容を入力して相談開始を実行する THE SYSTEM SHALL 入力された相談内容を起点とする相談状態を作成する。
- [ ] REQ-004: WHEN 相談状態の作成に成功する THE SYSTEM SHALL 最初の問いと現在の進行状況を表示し、後続の「不足情報の確認」機能へ進める状態にする。
- [ ] REQ-005: IF 相談内容が未入力または空白文字だけである THEN THE SYSTEM SHALL 相談状態を作成せず、相談内容の入力が必要であることを表示する。
- [ ] REQ-006: IF 相談開始処理が失敗する THEN THE SYSTEM SHALL 入力済みの相談内容を保持し、相談者が再試行できることを表示する。
- [ ] REQ-007: THE SYSTEM SHALL 相談開始時に入力された相談本文を一般ログへ無制限に出力せず、認証情報や秘密情報をクライアントコードまたは仕様へ埋め込まない。
- [ ] REQ-008: WHERE ローカル開発環境またはCloudflare previewである THE SYSTEM SHALL 相談開始から最初の問いと進行状況の表示までを検証可能にする。

## Acceptance criteria

- [ ] 自由記述欄に具体的なプレースホルダー例が表示される。
- [ ] 有効な相談内容を入力して開始すると、相談状態が作成され、最初の問いと進行状況が表示される。
- [ ] 空入力では相談が開始されない。
- [ ] 相談開始処理が失敗しても入力済み本文が失われず、再試行できる。
- [ ] この機能だけでは13項目の聞き取りやAI仮説生成へ踏み込まない。

## Confirmed product decisions from mockup review

- 相談の入口は自由記述とする。
- 入力者が何を入力すればよいか迷わないよう、入力欄には具体例をプレースホルダーで示す。
- 後続の不足情報確認では、5カテゴリ・13項目の進捗を継続表示する方針とする。ただし具体的なUIと進捗計算は本SPECでは決めない。
- 後続の不足情報確認では「未回答」と「わからない」を区別する方針とする。ただし状態モデルは本SPECでは決めない。
- AI仮説と相談者の確認済み事実の分離、およびAIによる可能性探索の原則は `docs/design-docs/open-innovation-ai-hypothesis-principles.md` に記録し、本SPECには実装しない。

## Out of scope

- 5カテゴリ・13項目を使った不足情報の聞き取りと回答状態管理
- 「わからない」回答の具体的なUI・保存形式・状態遷移
- 13項目の進捗表示の具体的なUI・計算方法
- AIによる質問生成、解釈、共創仮説の生成
- AI仮説の採用・修正・却下
- 課題プロフィールの生成、確認、修正、確定
- 候補組織の取得・評価・表示
- 認証・組織管理
- 相談データの保持期間、削除方法、正式運用時のアクセス制御方式

## Dependencies and handoff

この機能が受け入れ可能になった後、次の独立した縦切りとして「不足情報の確認（名称は仮）」を仕様化する。

「最初の問いと現在の進行状況を表示する」ことは `FR-001` の相談開始完了条件として本SPECに含めるが、その問いへの回答処理、次の問いの選択、13項目の状態更新は後続SPECの責務とする。

## Constitution alignment

- `P-001`: 相談者自身の自由記述を事実の起点とし、この機能ではAIによる事実補完を行わない。
- `P-005`: 相談本文を一般ログへ無制限に出さず、秘密情報の扱いに配慮する。
- `P-006`: 開始処理の失敗時にも入力済み内容を失わせず、再試行経路を提供する。
- `P-007`: React/Vite、Hono、Cloudflare Workersの責務境界を前提とする。具体的なAPIや保存方式はdesignで決める。
- `P-008`: 実装前に本SPECを人間レビューし、完了は検証根拠で判断する。
