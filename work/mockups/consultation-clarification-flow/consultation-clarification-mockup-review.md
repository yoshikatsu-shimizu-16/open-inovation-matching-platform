# 相談・課題明確化フロー モックアップ レビュー観点

## このモックの位置づけ

`docs/project-requirements.md` と `docs/constitution.md` を前提に、段階1「相談と課題の明確化」の画面遷移と人の確認境界を確認するための一時モック。

実装仕様、確定デザイン、API・データモデルの承認を意味しない。実データ保存、外部AI接続、認証、候補評価は行わない。

## 選択した利用者フロー

主利用者: 相談者

1. 自分の言葉で相談を開始する。
2. 5カテゴリ・13項目の不足情報を確認する。
3. 分からない項目は「未確認」のまま進める。
4. AIが整理した共創仮説を、相談者が確認・修正する。
5. 課題プロフィールの下書きを項目ごとに確認・修正する。
6. 相談者が明示的に課題プロフィールを確定する。
7. 確定版だけを次の候補評価フローへ渡す。

今回のモックはここで終了し、候補評価は別の縦切りとして扱う。

## 対応する全体要求

- FR-001: 相談開始と相談状態の開始イメージ
- FR-002: 5カテゴリ・13項目の確認状況
- FR-003: 根拠のない事実補完を避け、確認済み・未確認を区別する見せ方
- FR-004: 共創仮説の確認・修正
- FR-005: 課題プロフィール下書きの確認・修正
- FR-006: 明示的な確定操作と、確定前は候補評価へ進めない境界

主に P-001、P-002、P-003、P-006 の考え方を画面上で確認する。

## モック上の仮置き

正式な13項目名は参照先資料との照合前提であり、このモックでは5カテゴリを次の13項目へ仮分解している。

- 目的・背景・困りごと: 目的 / 背景 / 困りごと
- 保有能力・提供資源: 保有能力 / 提供資源
- 不足能力・ギャップ: 不足能力 / ギャップ
- 相手種別・連携形態: 相手種別 / 相手への期待 / 連携形態
- 条件・制約: 必須条件 / 制約 / 未確認事項

表示文言、質問文、サンプル回答、配色、レイアウトもすべてレビュー用の仮置き。

## このモックで確認したい問い

1. 相談開始時に自由記述から始める流れは自然か。
2. 5カテゴリ・13項目の進捗を、相談者に常時見せる必要があるか。見せる場合、この粒度でよいか。
3. 「分からないので未確認にする」という操作は、相談者にとって分かりやすいか。
4. 「確認できた事実」と「共創の可能性（仮説）」を別領域に分ける表現は適切か。
5. 課題プロフィールを項目別に編集し、最後に明示的な「確定」を要求する流れは自然か。
6. 確定操作前に、どの程度の未確認事項を許容するか。これは画面ではなく業務判断として決める必要がある。
7. 確定後に修正したい場合、「確定版 v2」を作るのか、確定を解除するのか。版管理ルールは後続SPECで決める必要がある。

## 人間が決める業務判断

- 正式な13項目と、それぞれを必須確認・任意確認のどちらにするか。
- 未確認項目が残っている状態で課題プロフィールを確定可能にする条件。
- 共創仮説を必須確認ステップにするか、課題プロフィール内へ統合するか。
- 課題プロフィール確定後の再編集・再確定の扱い。
- 相談途中の離脱・再開を初期版でどこまで提供するか。

## 検証する仮説

- 進捗を左側に常時表示すると、「AIと雑談している」のではなく、課題整理を進めている感覚を持ちやすい。
- 未確認を明示的な状態として見せることで、AIが勝手に穴埋めしていないことを理解しやすい。
- 仮説確認と課題プロフィール確定を分離すると、人の確認境界が分かりやすい。
- 候補評価へ進む前に「確定」という操作を置くと、FR-006 / P-002 の境界をUI上でも明確にできる。

## 未決事項

- 13項目の正式名称・質問順序・深掘り条件。
- AIが質問理由や出典をどこまで画面に見せるか。
- 対話形式とフォーム形式の比率。すべてチャットにするか、カテゴリごとにフォームを混ぜるか。
- 相談状態の保存タイミングと保持期間。
- 確定版の版管理と、再編集時の履歴表示方法。
- エラー時の再試行UI。FR-010 / P-006 は正常系の画面合意後に別状態としてモック確認する。

## 却下・保留

今回のモックには次を入れない。

- 候補一覧、ランキング、評価根拠の詳細表示
- 認証・組織管理
- 候補組織の登録・審査
- 専門家ルール管理
- 本番向けのデザインシステム
- 実AI、実API、永続化

## 次工程に向けた機能分割のたたき台

モック確認後、機能別SPECはシステム全体ではなく、利用者が独立した価値を確認できる縦切りに分ける。

候補:

1. **相談開始と不足情報ヒアリング**: FR-001〜003を中心に、相談開始、5カテゴリの確認、未確認状態まで。
2. **共創仮説の確認・修正**: FR-004を中心に、仮説提示、人の修正・確認まで。
3. **課題プロフィールの確認・確定**: FR-005〜006を中心に、下書き編集、明示的確定、確定版生成まで。
4. **候補評価と根拠確認**: FR-007〜009を中心に、段階2として別モック・別SPECで扱う。
5. **障害回復と相談再開**: FR-010〜011を、主要正常系の合意後に横断的な縦切りとして扱う。

最初に詳細SPECへ進める対象は、モックレビュー後に人間が一つ選ぶ。
